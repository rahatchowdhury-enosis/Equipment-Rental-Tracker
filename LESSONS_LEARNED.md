## Domain: Infrastructure
### Component: Project Scaffold & Auth
- **Issue:** [TASK-1] - Laravel Project Scaffold, Breeze Auth, Xdebug Config
- **Lesson:** Planned MySQL/MariaDB stack was switched to PostgreSQL + Laravel 12 mid-implementation — every `laravel/framework ^11.x` release available at the time carried unfixed security advisories, and local MySQL credentials couldn't be recovered, while a working local Postgres instance existed. Also: a stock Laravel config file (`config/database.php`) referencing a PHP-8.5-deprecated PDO constant silently broke session cookies by echoing a deprecation notice into the response body before headers were sent — status codes alone (200/302) did not reveal this; only inspecting raw response headers for a missing `Set-Cookie` surfaced it.
- **Action:** When bootstrapping a new Laravel app, run `composer audit` immediately after `create-project` and before committing to a framework minor version. When debugging "requests succeed but auth state doesn't persist," check for output printed before headers (deprecation notices, stray `echo`) rather than assuming the session driver is misconfigured. TASK-9 (which plans to add real content to `app/helpers.php`) and TASK-17 (README) should assume PostgreSQL, not MySQL — `REQUIREMENTS.md` and `designs/TASK-1.md`/`TASK-17.md` were updated accordingly. Note for whichever future task adds the deliberate raw-PDO query (REQUIREMENTS §4): `phpunit.xml` currently runs the test suite against in-memory SQLite, not Postgres, so a raw-SQL query written for Postgres syntax may pass tests without ever running against the real target DB — consider a dedicated Postgres-backed test for that one query.
